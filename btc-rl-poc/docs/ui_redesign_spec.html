UI/UX TEAM · SITE AUDIT & REDESIGN SPEC · 2026-08-28 · BTC 7PM ORACLE

Instrument Grade

The site reads as a research magazine about a trading system. The redesign makes it the system's own instrument panel — every number carrying its sample size, its floor, its freshness, and the version of the model that produced it. Audit first, then the target design, then a migration plan that follows the project's own champion/challenger rules.

CHARTER — NO OVERTURN.  This spec is strictly additive. No recorded decision is reversed: the ivory report default stays (theme.css records why the near-black terminal was rejected), metrics_lab's decision-impact ordering stays, the client-side recompute audit guarantee stays, and what the system computes is untouched. The redesign changes where each fact lives and how defensibly it is shown — nothing else.

Findings — ranked by decision impact

F1
HIGH

The experiment record has four competing sources of truth

ab_dashboard, experiment_review, metrics_lab's launch board, and sev0's champion table each render the treatment race from their own in-page JS. Four renderers of one SPRT state means four chances to disagree about the single most important fact the site reports: what is champion, and why.

One Experiments surface owning the treatment board; every other page links to it. The SPRT evidence bar becomes a shared component, rendered from results/treatments.json only.

F2
HIGH

Headline numbers ship without n, floor, or interval

Stat tiles show "59,799 scored point forecasts" style counts well, but skill numbers (Brier, win%, EV/$1) appear bare. The project's own core finding — direction accuracy 47–53% is indistinguishable from no skill — is invisible in a tile that says "51%". An MLE's dashboard never states a metric it cannot defend on sight.

Every stat tile carries: value · n · the floor it must beat (persistence MASE 1.0, market Brier, break-even win%) · a pass/fail skill badge. The math already exists in btc_rl/metrics.py; it needs a UI atom.

F3
HIGH

No global freshness or version stamp

Pages poll every 15s, but nothing tells the reader when data last arrived, which champion produced tonight's bets, or which code revision rendered the page. A stale tape is worse than no tape: it looks live.

A fixed status strip on every page: last-tick age (green <30s, amber <5m, red beyond), champion key + promoted_at stamp, active regime chip, data-source health. One shared module, one poll. Requires a small backend manifest — see the backend request list.

F4
MED

Two landings, one of them stale

index.html still opens the site in the training-era frame: MAE headlines (superseded by the 08-28 MSE switch), "open data streams verified 2026-08-21". A visitor who lands there reads last week's project.

Archive index.html behind an explicit "historical training record" banner and fold its agent-ladder and reward-design content into the Models surface. One landing: the Desk. The historical record is preserved, not deleted.

F5
MED

Duplicated in-page metric implementations

metrics_lab carries a Mann-Whitney AUC annotated "same implementation as sev0.html"; sev0 reimplements Platt fitting in JS. btc_rl/metrics.py solved this server-side ("every surface computes a given metric exactly one way") — the browser layer never got the same discipline, and copy-paste twins drift.

site/lib.js: one AUC, one Platt, one drawdown, one fee model, mirroring metrics.py function-for-function; pages import and render only. glossary.js established the shared-module pattern.

F6
MED

Editorial voice buries operational fact

Didot serif headlines, essay intros, and prose sections ("The tape & the desk — how this research would be used") read beautifully but scan slowly. On a desk surface the reader's questions are: position? P&L? regime? anything broken? Those answers currently live mid-paragraph.

Numbers and state first; prose demoted to expandable "why" notes under each module. The glossary panel (shipped) now carries the pedagogy, so body copy can shrink without losing the teaching mission.

F7
MED

Single light theme; no desk mode

theme.css records the decision: "the original near-black terminal read as shady; research should look like a research report." That decision stands — ivory stays the default. But a monitoring surface watched at night wants a dark ground, and the tokens are already centralized, so an additional mode costs one media query plus a toggle.

Keep ivory "print" as the default; add the dark "desk" mode via the same CSS variables, opt-in. Both palettes re-validated for CVD separation and contrast (the 10-series palette must be re-stepped for the dark ground).

F8
LOW

Every page recomputes everything from raw JSONL in-browser

metrics_lab states it recomputes the whole ladder from results/*.jsonl every 15s. Honest and auditable — this guarantee is kept — but redundant fetches across nine pages, and growing logs will eventually make first paint crawl.

Keep client-side recompute (it is the audit guarantee) but share one fetch/cache layer in lib.js, and ask backend for byte-offset checkpoints so pages can fetch deltas.

F9
LOW

Internal PM board mixed into the results site

board.html (owner queue, incidents) is a working artifact for the team, not a reader surface; its presence in the shared topnav dilutes the story the other pages tell.

Merge into the Method & Incidents surface with sev0's mitigation tracker and DECISIONS.md — one place where process lives.

F10
LOW

Terminology carries no on-ramp (now fixed, unwired)

The pages speak fluent SPRT/LLR/BSS/conformal with no reader assistance. The 62-entry clickable glossary (what / since / intuition / math / in-this-project / code) is built and verified — 75 terms wrap on metrics_lab alone — but no page loads it yet.

Wire <script src="glossary.js" defer></script> into all pages (coordinator task, already planned).

Target architecture — nine pages become five surfaces

The design language — what "made by an AI MLE" means concretely

Principle 1

The dashboard is the model's self-report

Every module answers: what do I believe, how sure am I, what would change my mind. Gates and thresholds (REGIME_FLOOR 0.62, SPRT boundaries, retrain gate) are drawn on the charts they govern — the reader sees the tripwire, not just the line.

Principle 2

No naked numbers

A metric renders only inside a StatTile that carries n, the relevant floor (persistence, market, break-even), and a skill badge. If n is too small to defend, the tile says so instead of showing a number — the metrics_lab "thin history" pattern, promoted to a site-wide law.

Principle 3

Provenance on every surface

Champion key + promotion stamp, data age, config constants in force, and the rendering revision, in a fixed strip. A screenshot of any page is a reproducible claim, not an anonymous chart.

Principle 4

Honesty affordances over decoration

The Monte-Carlo falsifiability cones, the baseline-vs-arm pairing, the family-wise-corrected boundaries — these are the personality of the site. The redesign gives them first-class visual treatment and cuts ornament that doesn't encode state.

Theme tokens — dual mode, one variable set

Ivory "print" stays the default (per the recorded decision in theme.css); dark "desk" ships as an opt-in equal citizen for live monitoring. Same token names the pages already use, so adoption is a toggle, not a rewrite. The 10-step series palette gets re-stepped for the dark ground and re-validated for CVD separation.

desk ground desk surface desk ink print ground print ink gauge amber (accent) up / good down / critical

Type: the Didot editorial voice concentrates where long-form belongs (Method & Incidents, the "why" notes). Instrument surfaces run a geometric sans display for section titles, the system sans for body, and the monospace stack for every digit, label, and stamp — tabular numerals throughout. Semantic color (up/down, good/critical) stays reserved and is never a series color; the amber accent marks proposals, gates, and attention, and appears nowhere else.
